Project goal
Build one AI chat application where users can choose Groq-hosted open-weight models, Google Gemini models, or verified free OpenRouter models. Users can send messages, switch models, compare answers side by side, inspect request latency/usage, and experience safe fallbacks if a provider is unavailable.

Two-phase architecture:
- Phase 1 (implement now): Unified multi-provider API gateway with robust streaming, model listing, comparison, history, quota protection, observable errors, authentication strategy and beautiful accessible UI. All development and default tests should work in a labeled mock mode without keys.
- Phase 2 (architect now; add only if time/environment allows): Optional self-hosted vLLM adapter for a small open-weight model, GPU instrumentation, request scheduling, cache experiments and real benchmark scripts. Do not present hosted API routing as original GPU inference optimization.
Technology
- Web: Next.js (App Router), TypeScript, React, Tailwind CSS, shadcn/ui, Lucide.
- Backend: Python, FastAPI, Pydantic, async httpx/provider SDKs, SSE streaming.
- Provider adapters: Groq, Google Gemini, OpenRouter, and optionally OpenAI-compatible local vLLM.
- Database: PostgreSQL with migration support; SQLite acceptable for local no-dependency setup.
- Redis: optional production rate-limit/session support; provide clear local development fallback.
- Observability: structured logs with request IDs, Prometheus-style metrics and simple UI analytics; optional OpenTelemetry.
- Testing: pytest, frontend component tests, Playwright, backend load testing (Locust or equivalent).
- Packaging: Docker and docker-compose for reproducible local startup where possible.
Core features — prioritize in order
P0: Functional core
1. Clean Gemini-inspired but original chat interface with conversation history, centered message list, responsive sidebar, typing/streaming, stop generation, regenerate and new chat.
2. Model selector grouping providers: Groq, Gemini, OpenRouter; display exact provider, model, free-tier eligibility and availability. Never hardcode guessed model IDs as current or free. Configurable allowlist/metadata checks must fail closed for unknown pricing or eligibility.
3. FastAPI unified endpoints: GET /health, GET /api/v1/models, POST /api/v1/chat/stream and POST /api/v1/chat/compare, plus appropriate history/session endpoints. Normalize provider-specific response events.
4. Real streamed responses over SSE (or equivalent), with clear request IDs, deltas, completion, usage, timeouts and error events. Support user cancellation and cleanup of abandoned streams.
5. Free-tier-only controls: disabled-by-default paid models, no silent upgrade to billed endpoints, clear rate-limit alerts, provider-level budget/config warnings, and explicit user notification on any allowed fallback. Never promise provider accounts cannot bill if billing is active.
6. An obvious MOCK MODE (no keys required): fake responses generated by a deterministic test adapter, visibly labeled and never presented as real model output.
P1: Portfolio-grade capabilities
7. Side-by-side comparison: send exactly the same prompt and selected context to 2–3 explicitly chosen free models. Stream each independently; display response, observed latency, request ID, available token usage, and errors.
8. Usage dashboard: request count, success/failure, end-to-end latency p50/p95, time-to-first-visible-token/chunk, quota/fallback events; show timeframe and sample size. Separate measured data from unavailable/provider-internal metrics.
9. Configurable smart router (simple deterministic heuristic first): choose among allowlisted free providers based on recent latency, availability and user preferences; demonstrate decisions and record routing evidence. Do not claim ML optimization if using rules.
10. Concurrency safety: async provider requests, bounded queues, per-user rate limits, provider 429 handling, timeouts and circuit breakers. Route fallback only to verified allowlisted free models.
11. Persist chats securely where configured; include deletion and privacy defaults. Never expose secrets, log prompts by default, or render untrusted model Markdown without sanitization.
12. Accessible light/dark mode; fully functional desktop, tablet and mobile with no scroll/keyboard overlap.
P2: Optional true inference infrastructure
13. Local vLLM-compatible adapter for self-hosted Qwen/GPT-OSS where hardware permits. On unsupported hardware provide instructions and mark feature unverified.
14. Real GPU metrics on local workers only; no fabricated provider GPU utilization.
15. Benchmark round-robin vs an implemented scheduling heuristic under reproducible synthetic workloads; label simulations vs real GPU tests distinctly.
Design contract — Gemini-inspired, not a copy
- Design for clarity and premium minimalism; quiet typography, pale backgrounds, clean surfaces, generous spacing, minimal blue accent, subtle animations, crisp hierarchy.
- Desktop: compact left sidebar with history; centered chat canvas; discreet top bar with model selector; fixed bottom composer; optional comparison/metrics panel only when requested.
- Mobile: collapsible nav drawer, full-viewport chat, working keyboard/safe-area composer, sticky header, side-by-side comparison becomes vertical tabs/cards, no horizontal overflow.
- Responsive layout at 375, 768, 1280 and 1920 pixels. Test light and dark modes.
- States: empty welcome, loading, streamed text, stopping, model unavailable, quota reached, disconnected, timeout, retry, comparison partially failed.
- Avoid neon, glassmorphism, oversized gradients, intrusive motion, bloated nav and nonfunctional controls. No Gemini logos or copied assets.
- Keep code modular, type-safe and accessible (keyboard focus, ARIA labels, contrast, reduced motion).
API and security constraints
- Call Groq, Gemini and OpenRouter using current official docs and configured backend environment variables; do not place secrets in frontend or repository.
- For OpenRouter allow only explicit verified free-model IDs (typically :free) or its explicitly free router. Check current model eligibility rather than assuming names stay the same.
- Rate limits, models and provider policies change: store them in configurable data and show actual provider errors. Do not invent rate limits or provide fake success states.
- Example environment variable names: GROQ_API_KEY, GEMINI_API_KEY, OPENROUTER_API_KEY, DATABASE_URL, REDIS_URL, MOCK_MODE, FREE_MODE_ONLY.
- Make mock-mode smoke tests run entirely offline. Enable live integration tests only with explicit environment toggle.
- Add validation, safe rendering, authentication/authorization where user state is persisted, security headers, CORS restrictions and proper error handling.
